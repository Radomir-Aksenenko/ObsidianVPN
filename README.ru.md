# Протокол Obsidian VPN (v2)

Высокопроизводительный антицензурный сетевой транспортный протокол третьего уровня (L3) со случайными диапазонами заголовков (Range IDs), составными сигнатурами CPS, маскировкой TLS 1.3 REALITY, многопоточным UDP-конвейером и встраиваемым кроссплатформенным SDK для создателей клиентских приложений.

Статус: бета-версия / открытая спецификация и эталонная реализация на Go

---

## Обзор

Obsidian работает на третьем сетевом уровне (L3). Протокол спроектирован для надежного обхода современных комплексов глубокого анализа пакетов (DPI, включая ТСПУ), предотвращения активного зондирования (active probing) и преодоления белых списков протоколов.

В отличие от прикладных прокси (VLESS, Shadowsocks, Trojan), Obsidian создает полноценный виртуальный сетевой интерфейс (TUN). Формируется прямой L3 IP-туннель с высокой скоростью (350+ Мбит/с), минимальной задержкой и нативной передачей UDP без деградации TCP-over-TCP.

Ядро протокола разработано с учетом легкого встраивания в сторонние клиентские приложения для **iOS**, **Android**, **Linux**, **macOS** и **Windows**.

## Архитектура и методы обхода блокировок

```
[ Интерфейс TUN (IP-пакеты уровня L3) ]
                    │
                    ▼
[ Движок адаптивного паддинга и фрейминга ]
  - Динамические Range-based Type IDs (4-байтные случайные типы)
  - Выравнивание размеров пакетов (квантование по корзинам)
                    │
                    ▼
[ Криптографический уровень ]
  - Аутентифицированное шифрование ChaCha20-Poly1305 AEAD
  - Обмен сессионными ключами X25519 / Постквантовый ML-KEM
  - Скользящее окно защиты от повторов (Replay Protection)
                    │
            ┌───────┴────────┐
            ▼                ▼
[ Управляющий канал и TCP ]  [ Скоростной UDP-конвейер ]
- Маскировка REALITY TLS 1.3 - Многопоточный Lock-Free конвейер
  (ретрансляция ClientHello) - Динамический port hopping и пул портов
- CPS-сигнатуры              - Фоновый шум и тайминг-джиттер
  (мимикрия под DNS/QUIC)    - Защита от статистического анализа
```

### 1. Рандомизация заголовков (Range-based Type IDs)
Большинство VPN-протоколов выдают себя первым же байтом: например, у WireGuard рукопожатие всегда начинается с `0x01`, а пакет данных с `0x04`. Системе ТСПУ или операторскому DPI достаточно одного простого правила, чтобы срезать такой трафик на лету.

В Obsidian статических идентификаторов пакетов нет. Протокол выбирает случайные 4-байтные числа из непересекающихся диапазонов:
- `Данные (Data)`: `0x10000000` - `0x1FFFFFFF` (более 268 миллионов комбинаций)
- `Keepalive`: `0x20000000` - `0x2FFFFFFF`
- `Шум (Noise)`: `0x30000000` - `0x3FFFFFFF`
- `Рукопожатие (Handshake)`: `0x40000000` - `0x4FFFFFFF`
- `Закрытие (Close)`: `0x50000000` - `0x5FFFFFFF`

Для внешнего анализатора каждый заголовок пакета выглядит как отрезок непредсказуемого энтропийного шума без постоянных сигнатур.

### 2. TLS-маскировка REALITY
Когда цензура включает белые списки и глушит любой нестандартный протокол:
- Первичное рукопожатие клиент упаковывает в валидный TLS 1.3 ClientHello.
- Протокол использует сертификаты реальных доверенных ресурсов (например, `www.microsoft.com` или `gateway.icloud.com`). Покупать домен и выпускать собственные сертификаты на сервере не нужно.
- Если со стороны DPI прилетает активное зондирование (active probing), сервер прозрачно пересылает эти запросы на настоящий целевой веб-сервер. Цензор получает штатный ответ веб-узла и снимает подозрения.

### 3. CPS (Composite Packet Signatures)
В условиях, когда фильтры сбрасывают соединения без знакомых сигнатур первых пакетов, Obsidian подключает CPS-механизм. Стартовые пакеты маскируются под легитимные DNS-запросы или QUIC Initial, после чего сессия переходит в режим штатной передачи данных.

### 4. Скоростной UDP-конвейер и защита по размерам пакетов
- Границы случайного паддинга (padding min/max) размывают сигнатуры размеров пакетов, мешая статистическому анализу MTU.
- Внутри работает многопоточный безблокировочный конвейер без лишних аллокаций памяти. Он держит пропускную способность выше 350 Мбит/с с MTU 1420-1500 и автоматически зажимает MSS, предотвращая фрагментацию.

## SDK для разработчиков клиентских приложений

Для разработчиков клиентов предоставляется официальный встраиваемый SDK. Полное руководство с примерами кода на Kotlin и Swift доступно в [docs/CLIENT_INTEGRATION.md](docs/CLIENT_INTEGRATION.md).

### 1. Go Mobile SDK (`pkg/mobile`)
Пакет оптимизирован для `gomobile bind` и генерирует нативные библиотеки `.aar` (Android) и `.xcframework` (iOS/macOS):
- `StartTunnelWithFd`: передача файлового дескриптора Android `VpnService` напрямую в ядро Go.
- `StartPacketTunnel`: передача IP-пакетов в оперативной памяти для цикла `packetFlow` в `NEPacketTunnelProvider` на iOS.
- `SocketProtector`: механизм вызова `VpnService.protect(fd)` перед установкой соединений, предотвращающий петли маршрутизации.
- `StartLocalProxy` / `StopLocalProxy`: запуск локального SOCKS5-прокси (`127.0.0.1:10808`).

### 2. C-ABI (`bindings/c`)
Универсальный C-заголовок [bindings/c/obsidian.h](bindings/c/obsidian.h) и динамическая библиотека (`.so`, `.dylib`, `.dll`) для прямого вызова из:
- Flutter (через `dart:ffi`)
- React Native (через TurboModules или JNI)
- Rust, C++, C#, Python

### 3. Кроссплатформенный TUN (`obsidian/tun`)
Абстракция виртуального сетевого адаптера для всех ОС:
- Linux: `/dev/net/tun` (`IFF_TUN | IFF_NO_PI`)
- macOS: `utun` (`com.apple.net.utun_control`)
- Windows: Wintun
- Универсальный: `OpenFD` для готовых системных дескрипторов

## Спецификация URI Obsidian

Для легкого обмена настройками серверов, интеграции в сторонние клиенты и поддержки подписок протокол использует единый формат ссылок.

### Формат ссылки

```
obsidian://<server_public_key>@<server_host>:<server_port>?[параметры]#[имя_сервера]
```

Также парсер принимает альтернативные префиксы:
- `vpn://obsidian/<server_public_key>@<server_host>:<server_port>?[параметры]#[имя_сервера]`
- `vpn://<server_public_key>@<server_host>:<server_port>?proto=obsidian&[параметры]#[имя_сервера]`

### Параметры строки запроса

| Параметр | Тип | Назначение | Значение по умолчанию |
|:---|:---|:---|:---|
| `udp_port` | integer | Порт скоростного UDP-канала данных | Равен `server_port` |
| `udp_data` | `0` или `1` | Использование ускоренного UDP-канала | `1` |
| `security` | string | Режим маскировки (`reality` или `none`) | `reality` |
| `sni` | string | Домен маскировки TLS / REALITY | `www.microsoft.com` |
| `auth_key` | hex string | Ключ авторизации фильтра REALITY | Необязательно |
| `fp` | string | Слепок TLS-клиента (`chrome`, `ios`, `firefox`) | `chrome` |
| `profile` | string | Пресет обфускации (`fast-secure`, `stealth`, `default`) | `fast-secure` |
| `mtu` | integer | Размер MTU туннеля | `1420` |
| `dns` | string | DNS-сервер внутри туннеля | `1.1.1.1` |
| `ipv6` | `0` или `1` | Маршрутизация IPv6 (Dual-Stack) | `0` |
| `noise_min` | float | Минимальный интервал отправки шума (сек) | `10` |
| `noise_max` | float | Максимальный интервал отправки шума (сек) | `40` |
| `keepalive` | float | Периодичность проверки доступности (сек) | `20` |
| `junk` | integer | Количество мусорных пакетов при старте | `7` |
| `sig` | string | CPS-сигнатура (может повторяться несколько раз) | Встроенные по умолчанию |
| `keyserver`| URL | Эндпоинт сервера ключей (учет устройств и подписок) | Необязательно |
| `token` | string | Токен доступа клиента | Необязательно |
| `expires` | ISO 8601 | Срок действия доступа | Необязательно |

### Пример ссылки

```
obsidian://170a2fec63c53e4a0c6c866d9d08a3304602b3a9090101765af292a469ac1f27@198.51.100.1:8443?security=reality&sni=www.microsoft.com&auth_key=d859d03517492c93bbdf73a10bc10cf1&udp_port=8443#Frankfurt-01
```

## Сборка из исходников

### Требования
- Go 1.22 или выше
- Linux (для сервера TUN: утилиты `iproute2`, `iptables` или `nftables`)
- Windows / macOS / Linux (для клиента)

### Сборка CLI-клиента и сервера

```bash
# Сборка сервера (Linux)
go build -o bin/obsidian-server ./cmd/server

# Сборка CLI-клиента (Windows / Linux / macOS)
go build -o bin/obsidian-client ./cmd/client
```

### Сборка Mobile SDK

```bash
# Android AAR (требуется gomobile)
gomobile bind -target=android -androidapi=21 -o obsidian.aar ./pkg/mobile

# iOS XCFramework (требуется gomobile и macOS)
gomobile bind -target=ios,iossimulator -o Obsidian.xcframework ./pkg/mobile
```

### Сборка C-Shared библиотек

```bash
# Linux
go build -buildmode=c-shared -o libobsidian.so ./bindings/c

# macOS
go build -buildmode=c-shared -o libobsidian.dylib ./bindings/c

# Windows
go build -buildmode=c-shared -o obsidian.dll ./bindings/c
```
