# Протокол Obsidian VPN (v2)

Высокопроизводительный транспортный протокол L3-уровня для устойчивой связи в условиях жесткой цензуры и DPI. Сочетает динамические диапазоны заголовков (Range IDs), CPS-сигнатуры, TLS-маскировку REALITY и параллельный безблокировочный UDP-конвейер.

Статус: Бета / Открытая спецификация и эталонная реализация

---

## Обзор

Obsidian — это открытый сетевой протокол третьего уровня (L3), спроектированный для преодоления современных систем глубокого анализа пакетов (DPI, включая ТСПУ), активного зондирования (active probing) и белых списков протоколов.

В отличие от прикладных прокси (VLESS, Shadowsocks, Trojan), работающих на уровне отдельных TCP/SOCKS5-потоков, Obsidian поднимает полноценный виртуальный сетевой интерфейс (TUN). Это обеспечивает честный сквозной IP-туннель с высокой скоростью (350+ Мбит/с), минимальными задержками и отсутствием проблемы TCP-over-TCP при передаче UDP-трафика (онлайн-игры, видеозвонки, стриминг).

## Архитектура и методы обхода блокировок

```
[ Интерфейс TUN (IP-пакеты уровня L3) ]
                    │
                    ▼
[ Движок адаптивного паддинга и фрейминга ]
  - Динамические Range-based Type IDs (4-байтные случайные типы)
  - Выравнивание размеров пакетов (квантование по корзинам)
                    │
                    ▼
[ Криптографический уровень ]
  - Аутентифицированное шифрование ChaCha20-Poly1305 AEAD
  - Обмен сессионными ключами X25519 / Постквантовый ML-KEM
  - Скользящее окно защиты от атак повторного воспроизведения (Replay Protection)
                    │
            ┌───────┴────────┐
            ▼                ▼
[ Управляющий канал и TCP ]  [ Скоростной UDP-конвейер ]
- Маскировка REALITY TLS 1.3 - Многопоточный Lock-Free пайплайн
  (ретрансляция ClientHello) - Пул портов и port hopping
- CPS-сигнатуры              - Фоновый шум и тайминг-джиттер
  (мимикрия под DNS/QUIC)    - Защита от статистического анализа
```

### 1. Рандомизация заголовков (Range-based Type IDs)
Классические VPN-протоколы используют фиксированные байты для идентификации пакетов (например, `0x01` для рукопожатия WireGuard, `0x04` для данных). Это позволяет DPI-системам блокировать протокол по простой сигнатуре первого байта.

В Obsidian статические идентификаторы заменены на случайные 4-байтные числа из непересекающихся диапазонов:
- `Данные (Data)`: `0x10000000` – `0x1FFFFFFF` (более 268 млн вариантов)
- `Keepalive`: `0x20000000` – `0x2FFFFFFF`
- `Шум (Noise)`: `0x30000000` – `0x3FFFFFFF`
- `Рукопожатие (Handshake)`: `0x40000000` – `0x4FFFFFFF`
- `Закрытие (Close)`: `0x50000000` – `0x5FFFFFFF`

С точки зрения DPI любой заголовок пакета выглядит как отрезок непредсказуемого энтропийного шума.

### 2. TLS-маскировка REALITY
Для сетей, где весь неизвестный трафик блокируется по умолчанию («белый список протоколов»):
- Клиент упаковывает первичное рукопожатие в подлинный TLS 1.3 ClientHello.
- Используются сертификаты реальных трастовых доменов (например, `www.microsoft.com`, `gateway.icloud.com`) без необходимости покупать собственный домен и выпускать сертификаты на сервере.
- Попытки активного прощупывания со стороны DPI прозрачно перенаправляются на настоящий целевой веб-сервер, вводя цензор в заблуждение.

### 3. CPS (Composite Packet Signatures)
Протокол поддерживает генерацию валидных начальных пакетов для маскировки под популярные сетевые протоколы (DNS-запросы, QUIC Initial), позволяя успешно проходить жесткие правила фильтрации по первым пакетам соединения.

### 4. Скоростной UDP-конвейер и защита по размерам пакетов
- Настраиваемые границы случайного паддинга (padding min/max) стирают сигнатуры размеров при передаче пакетов.
- Безблокировочная очередь обработки пакетов в памяти обеспечивает скорость свыше 350 Мбит/с с MTU 1420–1500 и автоматическим сжатием MSS.

## Спецификация URI Obsidian

Для совместимости, удобного обмена серверами и будущей поддержки подписок в экосистеме Obsidian принят единый формат URI-ссылок.

### Формат ссылки

```
obsidian://<server_public_key>@<server_host>:<server_port>?[параметры]#[имя_сервера]
```

Также парсер принимает альтернативные префиксы:
- `vpn://obsidian/<server_public_key>@<server_host>:<server_port>?[параметры]#[имя_сервера]`
- `vpn://<server_public_key>@<server_host>:<server_port>?proto=obsidian&[параметры]#[имя_сервера]`

### Параметры строки запроса

| Параметр | Тип | Назначение | Значение по умолчанию |
|----------|-----|------------|-----------------------|
| `udp_port` | integer | Порт скоростного UDP-канала данных | Равен `server_port` |
| `udp_data` | `0` или `1` | Использование ускоренного UDP-канала | `1` |
| `security` | string | Режим маскировки (`reality` или `none`) | `reality` |
| `sni` | string | Домен маскировки TLS / REALITY | `www.microsoft.com` |
| `auth_key` | hex string | Ключ авторизации фильтра REALITY | Необязательно |
| `fp` | string | Слепок TLS-клиента (`chrome`, `ios`, `firefox`) | `chrome` |
| `profile` | string | Пресет обфускации (`fast-secure`, `stealth`, `default`) | `fast-secure` |
| `mtu` | integer | Размер MTU туннеля | `1420` |
| `dns` | string | DNS-сервер внутри туннеля | `1.1.1.1` |
| `ipv6` | `0` или `1` | Маршрутизация IPv6 (Dual-Stack) | `0` |
| `noise_min` | float | Минимальный интервал отправки шума (сек) | `10` |
| `noise_max` | float | Максимальный интервал отправки шума (сек) | `40` |
| `keepalive` | float | Периодичность проверки доступности (сек) | `20` |
| `junk` | integer | Количество мусорных пакетов при старте | `7` |
| `sig` | string | CPS-сигнатура (может повторяться несколько раз) | Встроенные по умолчанию |
| `keyserver`| URL | Эндпоинт сервера ключей (учет устройств/подписок) | Необязательно |
| `token` | string | Токен доступа клиента | Необязательно |
| `expires` | ISO 8601 | Дата истечения доступа | Необязательно |

### Пример ссылки

```
obsidian://170a2fec63c53e4a0c6c866d9d08a3304602b3a9090101765af292a469ac1f27@198.51.100.1:8443?security=reality&sni=www.microsoft.com&auth_key=d859d03517492c93bbdf73a10bc10cf1&udp_port=8443#Frankfurt-01
```

### Архитектура подписок
Эндпоинт подписки отдает:
1. Обычный текст со списком ссылок `obsidian://...` по одной на строку, ЛИБО
2. Base64-кодированную строку этого списка.

## Руководство по интеграции в сторонние клиенты

Ядро Obsidian написано на чистом Go без зависимостей от CGO и может легко встраиваться в существующие VPN-клиенты как библиотека, фоновый сервис или через C-Shared биндинги.

### Использование пакета на Go

```go
package main

import (
    "log"
    "obsidian/obsidian"
)

func main() {
    uri := "obsidian://<pubkey>@198.51.100.1:8443?security=reality&sni=www.microsoft.com#Node"
    
    // 1. Разбор ссылки в объект конфигурации
    cfg, err := obsidian.ParseURI(uri)
    if err != nil {
        log.Fatalf("ошибка разбора URI: %v", err)
    }

    // 2. Генерация или чтение клиентской пары ключей
    clientKeys, _ := obsidian.GenerateKeypair()

    // 3. Подключение и запуск защищенной сессии
    log.Printf("Подключение к %s:%s через профиль %s...", cfg.ServerHost, cfg.ServerPort, cfg.Profile)
}
```

## Сборка из исходников

### Требования
- Go 1.22 или выше
- Linux (для сервера TUN: утилиты `iproute2`, `iptables` или `nftables`)
- Windows / macOS / Linux (для клиента)

### Компиляция сервера и клиента

```bash
# Сборка сервера (Linux)
go build -o bin/obsidian-server ./cmd/server

# Сборка CLI-клиента (Windows / Linux / macOS)
go build -o bin/obsidian-client ./cmd/client
```

### Запуск

#### Сервер
```bash
sudo ./bin/obsidian-server --config examples/server.example.json
```

#### Клиент
```bash
# Прямое подключение по ссылке:
sudo ./bin/obsidian-client --uri "obsidian://<key>@<host>:8443?security=reality&sni=www.microsoft.com#Beta"

# Либо подключение через файл конфигурации:
sudo ./bin/obsidian-client --config examples/client.example.json

# Экспорт существующего JSON в ссылку:
./bin/obsidian-client --config config.json --to-uri --label "MyServer"
```
